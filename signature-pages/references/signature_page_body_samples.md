# Signature Page Body Samples

Use this file as the direct drafting source for signature-page body structure when a matching file family exists. These complete desensitized sample blocks are bundled with the skill; they are not generic summaries or transaction facts.

Replace every placeholder using current source-supported values. Leave unsupported values blank or record an off-page open question under `signature_page_body_rules.md`.

The SHA/SPA examples illustrate detailed capacity labels using role placeholders beside the reusable drafting blocks. All company and person names are placeholders. Populate them only from the current source file or an approved current-matter instruction; example titles such as `Authorized Signatory` also require current source support.

## Placeholder Key

| Placeholder | Meaning |
| --- | --- |
| `[DOCUMENT FULL NAME]` | Full legal title of the current document. |
| `[DOCUMENT DEFINED TERM]` | Exact term by which the current document refers to itself. |
| `[PROJECT COMPANY FULL LEGAL NAME]` | Full legal name of the project or target company used for English footers. |
| `[TARGET COMPANY]` | Target or onshore company name used in Chinese no-text headers where source-supported. |
| `[HOLDER DEFINED TERM]` | Exact Holder / Registered Holder term in the Warrant. |
| `[COUNTERSIGNATURE LEGEND]` | Exact accepted/agreed/acknowledged legend used for the countersigning role. |
| `[PROMISOR DEFINED TERM]` | Exact Promisor / Commitment Party term. |
| `[RECIPIENT DEFINED TERM]` | Exact Recipient / accepting-party term. |
| `[SIGNING PARTY FULL LEGAL NAME]` | Full legal name of the party signing this page. |
| `[SIGNING PARTY SHORT NAME]` | Source-supported short name only if the output convention requires it. |
| `[AUTHORIZED SIGNATORY NAME]` | Named signatory only where the source requires or supports a named signer. |
| `[NATURAL PERSON NAME]` | Source-supported natural-person signing name. |
| `[CHINESE ORIGINAL NAME]` | Chinese original name used only when source-supported. |
| `[CAPACITY / TITLE]` | Source-supported signing capacity or title. |
| `[DOCUMENT ROLE]` | File-specific role such as lender, borrower, principal, agent, shareholder, director, company, or investor. |
| `[SOURCE-SUPPORTED GROUP LABEL]` | File-specific capacity label. For SHA/SPA, derive from `source_group_label_exact` and `final_capacity_label_for_signature_page` in the schedule group trace matrix. |
| `[DATE]` | Date only when the source requires a date value; otherwise keep the date line blank. |

| `Name:  [AUTHORIZED SIGNATORY NAME]` | `Name: [AUTHORIZED SIGNATORY NAME if source-required; otherwise leave blank]`; use a named signatory only where source-supported or user-approved for the current matter. |


## Memorandum And Articles Of Association


### Variant CL-3 - Recipient / Accepting Party Page

Repeat the same document-level `IN WITNESS WHEREOF` clause from CL-1 or CL-2, then use the exact current Commitment Letter acceptance legend.

```text
	IN WITNESS WHEREOF, the [PROMISOR DEFINED TERM] [has/have] executed this Commitment Letter as of the date first written above.

[COUNTERSIGNATURE LEGEND]

[RECIPIENT DEFINED TERM]:
[SIGNING PARTY FULL LEGAL NAME]
By: _________________________
Name: [AUTHORIZED SIGNATORY NAME if source-required; otherwise leave blank]
Title: [CAPACITY / TITLE]

SIGNATURE PAGE OF [DOCUMENT FULL NAME] OF [PROJECT COMPANY FULL LEGAL NAME]
```

Allowed legends must come from the current Commitment Letter, such as `ACCEPTED AND AGREED:`, `ACCEPTED AND AGREED TO AS OF THE DATE FIRST WRITTEN ABOVE:`, or `THE PROVISIONS OF THIS COMMITMENT LETTER ARE ACCEPTED AND AGREED TO AS OF THE DATE FIRST WRITTEN ABOVE:`. Put the party making the commitment in the Promisor / Commitment Party block, and put only an actual Recipient / Accepting Party below the special legend. Do not move a party under `ACCEPTED AND AGREED:` merely because it appears in the signing guidance. Do not delete `IN WITNESS WHEREOF`.
